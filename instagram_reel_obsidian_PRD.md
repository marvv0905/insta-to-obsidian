# PRD: Instagram Reel to Obsidian Second Brain Pipeline

## 1. Overview
An agentic workflow that automatically converts educational Instagram Reels sent by the user into structured, summarized Markdown notes stored in an Obsidian vault. The vault serves as both a personal knowledge base and a retrieval source for LLM-based querying.

## 2. Problem Statement
The user saves educational Instagram Reels to themselves but rarely revisits them, causing content to pile up unused. There is no structured system to capture, digest, and retain the knowledge from these reels.

## 3. Goals
- Reduce friction between "saving" a reel and "retaining" its knowledge.
- Automatically transcribe and summarize reel content into clean, readable notes.
- Store notes in Obsidian for personal reference and future LLM-assisted querying.

## 4. Non-Goals
- Not intended to archive non-educational or entertainment reels.
- Not intended to replace manual note-taking entirely; user may still edit/annotate summaries.

## 5. User Flow
1. User copies an Instagram Reel link and sends it to a Telegram/Discord bot.
2. Bot downloads the reel and extracts audio/video.
3. Reel is transcribed into text.
4. Transcript is summarized into a structured Markdown note (title, tags, key takeaways, full transcript).
5. Note is written into the Obsidian vault (via REST API, git sync, or synced folder).
6. User can browse notes manually or query them via an LLM/RAG plugin inside Obsidian.

## 6. System Architecture

| Component | Function | Suggested Tools |
|---|---|---|
| Bot intake | Receive reel link from user | python-telegram-bot, discord.py, or n8n/Make webhook |
| Downloader | Fetch reel video/audio | yt-dlp, instaloader, or third-party API (Supadata, ScrapeCreators, Apify) |
| Transcription | Convert audio to text | Whisper (self-hosted) or built-in transcript API |
| Summarization | Generate structured markdown summary | LLM API (GPT-4o-mini, Claude Haiku) or local model via Ollama |
| Vault writer | Save note into Obsidian vault | Local REST API plugin, Obsidian Git, or synced folder (Syncthing/Dropbox/iCloud) |
| Query layer | Enable LLM-based search over vault | Smart Connections, Smart Composer, or ObsidianRAG (Docker) |

## 7. Note Template (Output Format)
```
---
source: <reel_url>
date: <YYYY-MM-DD>
tags: [topic1, topic2]
---

# <Auto-generated Title>

## Summary
- Key point 1
- Key point 2
- Key point 3

## Full Transcript
<collapsed section with raw transcript>
```

## 8. Key Risks & Mitigations

| Risk | Mitigation |
|---|---|
| Instagram anti-scraping breaks self-hosted downloader | Use paid transcript API as fallback/primary |
| Summaries lose visual context (on-screen text, diagrams) | Capture keyframe screenshot or reel caption as supplement |
| Notes pile up unread, same as original problem | Add weekly digest note summarizing new entries |
| Inconsistent note structure hurts retrieval quality | Enforce fixed frontmatter + template across all notes |

## 9. Success Metrics
- % of saved reels converted into notes within 24 hours.
- User engagement: number of notes reviewed or queried per week.
- Retrieval accuracy when querying vault via LLM/RAG plugin.

## 10. Milestones
1. **MVP**: Manual link paste to bot to transcript to summary to markdown file in local folder.
2. **V1**: Automated vault write via REST API/git sync + consistent template.
3. **V2**: RAG plugin integration for LLM querying inside Obsidian.
4. **V3**: Weekly digest automation + visual context capture (screenshots/captions).
